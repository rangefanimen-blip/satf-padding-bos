# Протокол эксперимента v1

## Предобработка и время

Датасеты: MovieLens-1M, Amazon Beauty 2014 5-core, Amazon Video Games 2014 5-core. Любая оценка 1–5 означает факт взаимодействия, порог по рейтингу не применяется. Предсказывается следующее взаимодействие, а не положительное отношение. Используются только ID и timestamp; тексты, изображения и демография не используются.

События сортируются по `(timestamp, user_id, item_id)` со стабильной сортировкой. Для пары `(user,item)` сохраняется самое раннее событие. Повторы затем не являются целями. При одинаковом timestamp порядок по строковому ID условный, не восстановленный реальный порядок. Новая k-core-фильтрация не проводится. Предварительный 5-core Amazon построен владельцем по всей выборке: это ограничение отбора популяции.

`t1 = lower_quantile(timestamp, 0.8)`, `t2 = lower_quantile(timestamp, 0.9)` вычисляются после дедупликации. Train: `t < t1`; validation: `t1 <= t < t2`; test: `t >= t2`. Все равные timestamp остаются на одной стороне границы. Это приблизительные доли событий, не индивидуальный leave-last-out.

Каталог и словарь объектов строятся только из train. Модели обучаются один раз на train и не дообучаются на validation. На validation для каждого пользователя берётся первое новое событие интервала, история — события до t1. На test берётся первое новое событие после t2, история — события до t2, включая validation. Для этого первого события история совпадает с доступной до момента предсказания. В истории остаются известные train-каталогу объекты. Cold-target исключается, но НЕ заменяется следующим warm-target. Отдельно считаются исключения cold-target и отсутствие известной истории; счётчики последовательные и не перекрываются.

Длина доступной модельной истории — число известных к моменту предсказания объектов, обрезанное до K. При оценке из полного train-каталога исключается ВСЯ доступная история, а не только хвост K. Служебные объекты никогда не попадают в кандидаты. Равные score разрешаются по возрастанию индекса объекта; индекс задан строковой сортировкой train-ID.

## Кодировки и инференс

При n<K: Zero = q нулей + история; PAD = q наблюдений одного служебного объекта + история; BOS = q−1 нулей + одна метка + история. q=K−n. При n>=K берётся хвост K без служебных токенов. Сначала строится кодировка длины K, затем для прогнозирования она сдвигается на один шаг влево, последняя позиция остаётся неизвестной. После сдвига новый BOS не добавляется. Это сохраняет одинаковые входы Zero/PAD/BOS при полной истории.

В HOOI всегда резервируется одинаковая дополнительная строка каталога, даже для Zero, где она нулевая. В обучении одна последовательность на пользователя. Hankel длины K имеет размеры L×(K−L+1), элемент (a,b) равен x[a+b]. Свёртки выполняются через K разреженных пользователь–объект матриц; все позиции повторяющегося PAD учитываются. Полный четырёхмерный тензор создаётся только в тестах.

Основная конфигурация: K=50, L=5, ранги (12,12,2,2), 3 итерации HOOI, нижнетреугольное A[a,b]=(a−b+1)^−1 при a>=b. Нормировка частоты выключена (scaling=1). Все три кодировки имеют одинаковые начальные матрицы при одном seed. Включение нормировки задаётся весом объекта max(count,1)^((scaling−1)/2), count считается по реальным train-хвостам. Служебный вес по умолчанию равен 1. На выходе обратное масштабирование не применяется.

SASRec: собственная PyTorch-реализация causal attention, 1 блок и 1 голова, dim=32, dropout=0.2, Adam lr=0.001, betas=(0.9,0.98), batch=128, 5 эпох. Обучение на последних K пар next-item каждого train-пользователя с >=2 событиями. BCE с одним равномерным отрицательным объектом на положительный, исключены только объекты train-истории пользователя. У модели нет доступа к будущим validation/test-положительным объектам при sampling. MostPopular считает все реальные train-взаимодействия; это диагностический бейзлайн без настройки.

## Бюджет, метрики и неопределённость

Пилот использует одну заранее зафиксированную конфигурацию на модель, без выбора по test и без заявления об оптимальности. Seeds: 17,29,43. MostPopular детерминирован и запускается один раз. Между семействами не уравнивается wall-clock: 3 шага HOOI и 5 эпох SASRec не равнозначны степени сходимости. Значения validation сохраняются для будущего подбора, текущая конфигурация по ним не выбиралась.

Один target на пользователя. NDCG@10 = 1/log2(rank+1), если rank<=10, иначе 0. HR@10 = 1[rank<=10]. Оценка по полному допустимому каталогу, без negative sampling. Среднее по пользователям, затем среднее и SD по seed. Отдельные срезы: n<K, n=K и интервалы 1–5,6–20,21+ (n вычислено в момент предсказания).

Парный bootstrap: усреднить NDCG каждого пользователя по трём seed, затем 2000 раз переотобрать пользователей с возвращением; показать percentile 95% CI разности с Zero. Интервал условен на этих seed и не покрывает полностью неопределённость обучения. Три запуска не позволяют надёжно оценить её хвосты. При множественных контрастах не делается заявление о подтверждённой статистической значимости.

Время обучения включает построение представления, fit и подготовку проектора; загрузка/предобработка данных исключены. Время оценки включает score, маскирование и вычисление ранга. Peak RSS — максимум памяти всего отдельного процесса, семплируемый каждые 20 мс во время fit+eval; это НЕ размер модели и НЕ GPU VRAM. Для текущих измерений модели запускаются последовательно на CPU, 2 вычислительных потока. Colab GPU-запуски записываются в отдельную папку и не смешиваются с CPU-временем.

## Диагностика механизма

`configs/ablations.json`: PAD/sqrt(q) уравнивает суммарный квадрат веса служебных записей в исходном позиционном тензоре (но не после Hankel/A). Leftmost marker ставится в нулевую позицию пустого префикса и удаляется при сдвиге инференса; это контроль влияния служебного наблюдения в обучении. Варианты scale=0.2 сравнивают Zero/PAD/BOS при нормировке реальных объектов, а PAD frequency дополнительно нормирует служебный токен по его train-частоте. Эти контрасты диагностические: они не являются полной причинной идентификацией отдельного механизма.
