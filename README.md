# Паддинг и метка начала истории в тензорных последовательных рекомендациях

Исследовательский проект о влиянии кодировки незаполненных позиций истории на качество и скорость LA-SATF.

**Статус:** подготовлен proposal; экспериментальных результатов пока нет.

Материалы: [proposal](docs/proposal.pdf) · [презентация PowerPoint](docs/presentation.pptx) · [презентация PDF](docs/presentation.pdf) · [текст выступления на 7 минут](docs/talk.md).

## Задача

По хронологической истории взаимодействий пользователя предсказать следующий новый для него объект. На вход подаются идентификаторы объектов; на выходе — ранжирование ещё не просмотренных объектов каталога. Тексты и изображения в моделях не используются.

Проверяем, помогает ли явное кодирование доступной длины истории улучшить NDCG@10 относительно нулевого паддинга, как эффект зависит от длины истории и может ли один токен BOS дать сопоставимое качество с повторяемым PAD при меньших затратах времени.

## Подход

Основа — LA-SATF из [статьи Frolov и Oseledets](https://doi.org/10.1109/ACCESS.2023.3234863) и [авторский код SATF](https://github.com/recspert/SATF). Метод строит четырёхмерное Hankel-представление позиционного тензора и обучает Tucker-разложение методом ALS/HOOI.

Для одной и той же истории из `n < K` реальных событий сравниваем три кодировки фиксированной длины `K`; `q = K − n`:

| Вариант | Представление | Что означает префикс |
|---|---|---|
| Zero | `[0, …, 0, i₁, …, iₙ]` | `q` нулевых позиций — отсутствие наблюдений |
| PAD | `[PAD, …, PAD, i₁, …, iₙ]` | `q` положительных записей одного служебного объекта |
| BOS | `[0, …, 0, BOS, i₁, …, iₙ]` | `q − 1` нулей и одна метка начала доступной истории |

При `n = K` служебные токены не добавляются и все варианты совпадают. Более длинные истории обрезаются до последних `K` событий. PAD и BOS исключаются из кандидатов рекомендации.

Самостоятельная часть проекта — реализация PAD/BOS, проверка разреженных Hankel-операций для повторяющегося PAD и сравнительные эксперименты.

## Оценка и эксперименты

- Основная метрика — **NDCG@10**; дополнительно измеряем время обучения и инференса.
- Бейзлайны — [SASRec](https://arxiv.org/abs/1808.09781) и исходная LA-SATF с нулевым паддингом (Zero).
- Сравниваем Zero, PAD и BOS при различных длинах истории и нескольких случайных инициализациях.
- Варьируем ранги разложения, размер локального окна, затухание позиционных весов и нормализацию популярности LA-SATF.

Вычисления планируются на бесплатных ресурсах Google Colab: CPU для LA-SATF, GPU для SASRec. Повторяемый PAD может увеличить расход памяти и время обучения; для этого предусмотрены разреженные операции и ограничение рангов. Минимальный результат — воспроизведение LA-SATF и сравнение трёх кодировок на MovieLens-1M.
